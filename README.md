# 게임 길드 홍보용 정적 웹사이트

다크 판타지 분위기의 길드 홍보 페이지입니다. GitHub Pages에 올리면 방문자는 `index.html`을 보고, 실제 홍보 내용은 같은 폴더의 `data.json`에서 불러옵니다.

## 파일 역할

- `index.html`: 방문자가 보는 길드 홍보 페이지입니다. 같은 폴더의 `data.json`을 읽어서 화면을 만듭니다.
- `admin.html`: 내용을 수정하고 새 `data.json`을 만드는 관리 페이지입니다.
- `data.json`: 실제 배포용 콘텐츠 데이터입니다. 모든 방문자에게 보이는 내용의 기준입니다.
- `assets/`: 직접 사용하는 이미지 파일을 넣는 폴더입니다. 예: `assets/intro.png`, `assets/hero.png`

## 콘텐츠 수정 절차

1. `admin.html`을 엽니다.
2. 메인 타이틀, 인트로, 아티클, 하단 안내 내용을 수정합니다.
3. `data.json 내보내기` 버튼을 누릅니다.
4. 다운로드된 `data.json` 파일을 확인합니다.
5. GitHub 저장소의 기존 `data.json` 파일을 새 파일로 교체합니다.
6. GitHub Pages 사이트에 접속해서 변경 내용을 확인합니다.

## 가장 중요한 운영 방식

모든 방문자에게 같은 최신 내용을 보여주려면 반드시 `data.json`을 GitHub 저장소에 올려야 합니다.

`admin.html`의 임시 저장 기능은 작성 중인 내용을 보호하기 위한 기능입니다. 이 임시 저장은 내 브라우저 안에만 남습니다. 그래서 내 컴퓨터에서는 수정한 내용이 보이더라도, 다른 방문자에게는 보이지 않습니다.

운영 반영 기준은 항상 아래 흐름입니다.

1. `admin.html`에서 수정
2. `data.json 내보내기`
3. GitHub 저장소의 `data.json` 교체
4. GitHub Pages에서 확인

이번 프로젝트에는 `admin.html`이 GitHub 저장소를 자동 수정하는 기능이 없습니다. 브라우저에서 GitHub 파일을 직접 바꾸려면 로그인, 저장소 권한, API 토큰 같은 처리가 필요해서 이 작업 범위에서는 제외했습니다.

## localStorage와 data.json 차이

- `localStorage`: 내 브라우저에만 저장됩니다.
- `localStorage`에 저장한 내용은 다른 방문자에게 보이지 않습니다.
- `data.json`: GitHub 저장소에 올라가는 실제 배포 데이터입니다.
- 모든 방문자에게 같은 내용을 보여주려면 새 `data.json`을 GitHub 저장소에 업로드해야 합니다.
- `admin.html`의 임시 저장은 작성 중 실수로 창을 닫았을 때를 대비하는 기능입니다.

## data.json 구조

`data.json`은 크게 5개 영역으로 나뉩니다.

- `site`: 버전과 수정일 정보입니다.
- `theme`: 전체 테마와 폰트 같은 디자인 설정입니다.
- `layout`: 아티클 카드 배치 같은 레이아웃 설정입니다.
- `hero`: 첫 화면의 타이틀, 타이틀 글씨 크기, 설명, 대표 이미지 정보입니다.
- `intro`: 접속 시 보이는 로딩 인트로 설정입니다.
- `articles`: 중앙 카드 영역에 들어가는 여러 개의 홍보 글입니다.
- `gallery`: 홍보 사진을 여러 장 보여주는 갤러리 영역입니다.
- `footer`: 하단 가입 및 문의 안내입니다.

아티클 본문은 여러 줄 bullet로 표시됩니다. `admin.html`에서는 본문 입력칸에 한 줄씩 적으면 한 줄당 하나의 bullet로 저장됩니다.

사용 가능한 글머리 기호 스타일:

- `dot`: ●
- `arrow`: ▸
- `star`: ✦
- `none`: 글머리 기호 없음

사용 가능한 폰트 크기:

- `small`
- `medium`
- `large`

## 전체 테마와 폰트 바꾸는 방법

`admin.html`의 `전체 디자인` 영역에서 전체 테마와 전체 폰트를 선택할 수 있습니다.

테마는 사이트 전체의 색상, 카드 모양, 메인 화면 분위기, 여백감, 배경 에셋을 바꿉니다.

선택 가능한 테마:

- `신성한 다크 판타지`: 기존 기본 테마입니다. 검정 배경, 금색 포인트, 판타지 길드 홍보에 맞춘 스타일입니다.
- `Apple 갤러리`: 밝은 흰색/파치먼트 배경, 절제된 UI, 큰 메인 화면 중심의 미니멀한 제품 갤러리 느낌입니다.
- `Bugatti 블랙 럭셔리`: 순수 블랙, 흰색 타이포그래피, 각진 카드, 넓은 자간을 쓰는 럭셔리 자동차 브랜드 느낌입니다.
- `Notion 컬러 워크스페이스`: 네이비 메인 화면, 보라색 포인트, 흰 카드와 컬러풀한 장식감이 있는 생산성 툴 느낌입니다.
- `Claude 크림 에디토리얼`: 따뜻한 크림 배경, 코랄 포인트, 차분한 에디토리얼 AI 서비스 느낌입니다.
- `문라이트 드림`: 달빛, 별, 은은한 보라빛을 쓰는 부드럽고 몽환적인 판타지 느낌입니다.

테마용 배경 이미지는 `assets/themes` 폴더에 들어 있습니다. GitHub에 올릴 때 이 폴더도 함께 업로드해야 테마 배경이 정상적으로 보입니다.

테마를 바꾼 뒤에도 운영 반영 방법은 같습니다. `data.json 내보내기`를 누르고 GitHub 저장소의 기존 `data.json`을 새 파일로 교체하세요.

`data.json`에는 아래처럼 저장됩니다.

```json
"theme": {
  "fontFamily": "system",
  "preset": "celestial"
}
```

`preset` 값은 `celestial`, `apple`, `bugatti`, `notion`, `claude` 중 하나입니다.

폰트도 같은 `전체 디자인` 영역에서 선택할 수 있습니다.

선택 가능한 값:

- `기본 고딕`: 대부분의 기기에서 무난하게 보이는 기본 폰트입니다.
- `Noto Sans KR`: 가장 무난하고 읽기 좋은 한글 고딕입니다.
- `Noto Serif KR`: 고급스럽고 차분한 한글 명조입니다.
- `나눔고딕`: 친숙하고 안정적인 한글 고딕입니다.
- `나눔명조`: 문서처럼 정돈된 한글 명조입니다.
- `고운돋움`: 부드럽고 차분한 한글 고딕입니다.
- `고운바탕`: 판타지 분위기와 잘 어울리는 한글 바탕체입니다.
- `도현`: 제목이 굵고 강하게 보이는 한글 폰트입니다.
- `검은고딕`: 매우 굵고 강렬한 제목용 한글 폰트입니다.
- `명조 판타지`: 판타지 홍보 페이지에 어울리는 세리프 계열 느낌입니다.
- `깔끔한 UI 고딕`: 조금 더 정돈된 UI 느낌입니다.
- `둥근 고딕`: 부드러운 분위기의 폰트입니다.

폰트를 바꾼 뒤에도 운영 반영 방법은 같습니다. `data.json 내보내기`를 누르고 GitHub 저장소의 기존 `data.json`을 새 파일로 교체하세요.

일부 폰트는 Google Fonts에서 불러오는 웹폰트입니다. GitHub Pages 방문자가 인터넷에 접속해 있으면 자동으로 적용됩니다. 폰트를 불러오지 못하는 환경에서는 기본 한글 폰트로 대체되어 글자가 깨지지 않게 표시됩니다.

## 이미지 넣는 방법

첨부 이미지는 무드 참고용입니다. 실제 인트로 이미지나 대표 이미지로 자동 사용되지 않습니다. 사용할 이미지는 직접 준비해야 합니다.

내부 이미지 파일을 사용할 때:

1. 원하는 이미지를 `assets` 폴더에 넣습니다.
2. `admin.html`을 엽니다.
3. 대표 이미지 경로에는 `assets/hero.png`처럼 입력합니다.
4. 인트로 이미지 경로에는 `assets/intro.png`처럼 입력합니다.
5. `data.json 내보내기`를 누릅니다.
6. GitHub 저장소에 새 `data.json`과 `assets` 폴더의 이미지 파일을 함께 업로드합니다.

외부 이미지 URL도 사용할 수 있습니다.

예:

- `assets/intro.png`
- `assets/hero.png`
- `https://example.com/image.png`

이미지 값이 비어 있거나 이미지 로딩에 실패하면 금빛 다크 판타지 fallback 디자인이 표시됩니다.

## 메인 타이틀 상단 문구, 줄바꿈, 이미지 위치 조정

`admin.html`의 메인 타이틀 영역에서 `메인 타이틀 상단 작은 문구`를 수정할 수 있습니다. 기본값은 `MMORPG Guild Recruitment`입니다.

메인 타이틀 입력칸은 여러 줄 입력을 지원합니다. 원하는 위치에서 Enter를 누르면 방문자 페이지에서도 같은 줄바꿈으로 표시됩니다.

`메인 타이틀 글씨 크기`에서 작게, 보통, 크게, 아주 크게를 고를 수 있습니다. 이 값은 `메인 타이틀 위치`와 별도로 저장되므로 타이틀을 이미지 아래로 내려도 글씨 크기를 따로 유지하거나 키울 수 있습니다.

대표 이미지가 위나 아래로 잘려 보이면 `대표 이미지 위치`를 바꿔보세요.

- `위쪽을 더 보여주기`: 이미지의 위쪽을 기준으로 보여줍니다.
- `약간 위로 올리기`: 현재보다 이미지 기준점을 조금 위로 올립니다.
- `가운데 기준`: 기본값입니다.
- `약간 아래로 내리기`: 현재보다 이미지 기준점을 조금 아래로 내립니다.
- `아래쪽을 더 보여주기`: 이미지의 아래쪽을 기준으로 보여줍니다.

위치 조정 후에도 실제 사이트에 반영하려면 `data.json 내보내기`를 누르고 GitHub 저장소의 기존 `data.json`을 교체해야 합니다.

대표 이미지와 타이틀이 겹쳐 보이면 `메인 타이틀 위치`를 바꿔보세요.

- `기본 위치`: 테마 기본 위치를 사용합니다.
- `조금 아래로`: 타이틀 영역을 살짝 아래로 내립니다.
- `이미지 아래로 분리`: 대표 이미지 아래에 타이틀 영역을 별도로 배치합니다. 이 경우 이미지, 타이틀, 아티클 순서로 표시되어 서로 겹치지 않습니다.

## 인트로 문구 설정

`admin.html`의 Intro 영역에서 인트로 문구를 메인 타이틀과 다르게 설정할 수 있습니다.

- `인트로 문구`: 여러 줄 입력을 지원합니다. Enter를 누르면 인트로에서도 줄바꿈됩니다.
- `인트로 문구 정렬`: 가운데, 왼쪽, 오른쪽 정렬을 선택할 수 있습니다.

인트로 문구를 비워두면 현재 메인 타이틀을 기준으로 사용합니다.

## 아티클 배치와 표시 옵션

`admin.html`의 중앙 아티클 영역에서 각 아티클마다 `아티클 배치`를 선택할 수 있습니다.

- `전체: 한 줄에 1개`: 해당 아티클이 한 줄 전체를 차지합니다.
- `반 칸: 한 줄에 2개`: 해당 아티클이 반 칸을 차지합니다. 반 칸 아티클이 연속으로 두 개 있으면 한 줄에 두 개가 나란히 표시됩니다.

모바일 화면에서는 보기 좋게 자동으로 한 줄에 한 개씩 표시됩니다.

예:

- `전체, 반 칸, 반 칸`: 1-2 배치
- `반 칸, 반 칸, 전체`: 2-1 배치
- `반 칸, 반 칸, 반 칸, 반 칸`: 2-2 배치
- `전체, 전체`: 1-1 배치

아티클별 설정:

- `이모지`를 비워두면 이모지 칸이 사라지고 타이틀이 가운데 정렬됩니다.
- `글머리 기호`에서 `없음`을 선택하면 본문 앞의 ●, ▸, ✦ 표시가 사라집니다.

## 하단 안내 이미지 넣는 방법

`admin.html`의 하단 안내 영역에서 `하단 이미지 URL 또는 경로`를 입력할 수 있습니다.

예:

```text
assets/footer.png
```

이미지 경로를 입력하면 하단 안내 본문 바로 아래에 이미지가 표시됩니다. 비워두면 이미지 영역은 표시되지 않습니다.

## 갤러리 넣는 방법

`admin.html`의 `갤러리 영역`에서 사진을 여러 장 추가할 수 있습니다.

1. 사용할 이미지를 `assets` 폴더에 넣습니다.
2. `갤러리 사용`을 `사용`으로 바꿉니다.
3. `한 줄 사진 개수`를 선택합니다.
4. `사진 추가`를 눌러 이미지 경로와 alt 텍스트를 입력합니다.
5. `data.json 내보내기`를 누릅니다.
6. GitHub 저장소에 새 `data.json`과 이미지 파일을 함께 올립니다.

예:

```text
assets/gallery-1.png
assets/gallery-2.gif
assets/gallery-3.jpg
```

배치 예:

- 한 줄 사진 개수 `1`: 1-1-1 배치
- 한 줄 사진 개수 `2`: 2-2 배치
- 한 줄 사진 개수 `3`: 3-3 배치

모바일에서는 보기 좋게 자동으로 한 줄에 한 장씩 표시됩니다. PNG, JPG, GIF 모두 사용할 수 있습니다.

## data.json 교체 방법

GitHub 웹사이트에서 교체하는 일반적인 방법입니다.

1. GitHub 저장소로 이동합니다.
2. 기존 `data.json` 파일을 엽니다.
3. 편집 또는 업로드 기능으로 다운로드한 새 `data.json` 내용으로 교체합니다.
4. 변경 사항을 커밋합니다.
5. GitHub Pages 사이트에 다시 접속합니다.

이미지를 추가했다면 `assets` 폴더도 함께 올려야 합니다. 예를 들어 `data.json`에 `assets/hero.png`라고 적었다면 GitHub 저장소에도 `assets/hero.png` 파일이 있어야 합니다.

## GitHub Pages 반영 확인

GitHub Pages는 보통 자동으로 반영되지만, 저장소 변경 직후에는 몇 초에서 몇 분 정도 걸릴 수 있습니다.

확인 방법:

1. GitHub Pages 주소로 접속합니다.
2. 새로고침합니다.
3. 바로 바뀌지 않으면 조금 기다린 뒤 다시 새로고침합니다.
4. 계속 예전 내용이 보이면 브라우저 강력 새로고침을 해봅니다.
   - Windows: `Ctrl + F5`
   - Mac: `Command + Shift + R`

## 로컬 테스트 주의사항

`index.html`을 더블클릭해서 직접 열면 브라우저 보안 정책 때문에 `data.json`을 읽지 못할 수 있습니다.

GitHub Pages에서는 정상 동작합니다. 로컬에서 확인하려면 VS Code의 Live Server 확장 기능이나 간단한 로컬 서버를 사용하세요.

예:

```bash
python -m http.server 8000
```

그 다음 브라우저에서 아래 주소를 엽니다.

```text
http://localhost:8000/
```

## 문제가 생겼을 때 확인할 것

- `data.json` 파일명이 정확한지 확인합니다.
- `index.html`과 `data.json`이 같은 폴더에 있는지 확인합니다.
- `data.json`의 JSON 형식이 깨지지 않았는지 확인합니다.
- 이미지 파일 경로가 맞는지 확인합니다.
- `assets` 폴더와 이미지 파일이 GitHub에 올라가 있는지 확인합니다.
- GitHub Pages 반영에 시간이 조금 걸릴 수 있습니다.
- 브라우저 캐시 때문에 즉시 안 보이면 새로고침 또는 강력 새로고침을 해봅니다.

## 현재 구조의 한계

- `admin.html`은 GitHub 저장소를 자동으로 수정하지 않습니다.
- 관리자가 `data.json`을 내보낸 뒤 GitHub 저장소에서 직접 교체해야 합니다.
- 방문자 인증, 관리자 로그인, 서버 저장 기능은 포함되어 있지 않습니다.

이 구조는 GitHub Pages처럼 서버 없이 운영하는 정적 사이트에 맞춘 방식입니다. 파일 수가 적고, 관리자가 새 `data.json`만 교체하면 모든 방문자에게 같은 최신 내용을 보여줄 수 있습니다.
